# 演出提示单 · 小剧场排练

供小剧场排练使用的演出提示单网页应用。Node.js/Express 后端 + 原生前端（无构建步骤），数据保存在本地 JSON 文件中。

## 功能

- 每条提示包含：**名称、独占设备通道、持续秒数**
- 开始时间两种方式：
  - **固定演出秒数**（如第 120 秒开始）
  - **跟随提示**：另一条提示结束后再延迟若干秒开始
- 新增 / 修改提示后**自动重算所有后继提示**；**拒绝不存在的引用与循环依赖**（返回错误，不写入数据）
- 时间轴按通道分行，以**左闭右开区间** `[start, end)` 判定同通道重叠：**首尾相接不算冲突**；冲突提示与冲突时段以红色标出
- **冲突允许保留**，不会被拒绝，方便排练中逐步调整
- 页面内直接编辑提示，保存后立即查看重算结果与最新冲突标注
- 删除保护：被其他提示跟随的提示不可直接删除

## 一条命令启动（Docker）

```bash
docker compose up --build
```

依赖安装（`npm install`）与数据初始化（首次启动自动生成含示例数据的 `data/cues.json`）都已包含在该命令中。

启动后访问：**http://localhost:3000**

> 示例数据中故意包含一对灯光通道上的冲突（「第一幕灯效」与「特殊灯效(待调整)」），用于演示冲突标注。

## 本地开发（不用 Docker）

```bash
npm install
npm start
```

同样访问 http://localhost:3000 。

## 配置

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `3000` | 服务监听端口（网页访问端口） |
| `DATA_FILE` | `./data/cues.json`（容器内 `/app/data/cues.json`） | 提示数据 JSON 文件路径 |

Compose 默认将宿主机 `3000` 端口映射到容器 `3000`，数据通过命名卷 `cue-data` 持久化。如需改端口，修改 `docker-compose.yml` 中 `ports` 的左侧（如 `"8080:3000"` 后访问 http://localhost:8080）。

## 数据格式

`data/cues.json`：

```json
{
  "cues": [
    {
      "id": "uuid",
      "name": "开场音乐",
      "channel": "音响",
      "duration": 45,
      "start": { "type": "after", "cueId": "<另一条提示的 id>", "delay": 0 }
    },
    {
      "id": "uuid",
      "name": "开场灯光",
      "channel": "灯光",
      "duration": 30,
      "start": { "type": "fixed", "seconds": 0 }
    }
  ]
}
```

## API 简介

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/state` | 全部提示（含计算出的开始/结束时间）、通道列表、冲突对及各通道冲突时段 |
| `POST` | `/api/cues` | 新增提示；校验失败 / 引用不存在 / 循环依赖返回 `400` |
| `PUT` | `/api/cues/:id` | 修改提示并重算；校验失败 / 引用不存在 / 循环依赖返回 `400` |
| `DELETE` | `/api/cues/:id` | 删除提示；被跟随的提示返回 `400` |

所有写操作成功时返回与 `GET /api/state` 相同的全量重算结果，前端据此立即刷新。
